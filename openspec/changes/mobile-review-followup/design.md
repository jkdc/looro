# Design: Mobile review follow-up

## Basis

The authoritative findings and acceptance scenarios are R01–R19 in `informe-revision-implementacion-app-movil-2026-10-27.md`. Existing `openspec/changes/mobile-audit-remediation/` defines the original synchronization, ownership and voice contracts; this document narrows the remaining implementation work without replacing those contracts.

## Decisions and constraints

1. **Unattributed fallback (R01):** fail closed before reading or writing a legacy single-ownerless payload when account ownership cannot be proven. Preserve the existing bytes and backups. Expose a non-destructive retry/recovery path rather than suggesting erasure. Partitioned fallback would retain availability but requires assigning unproven ownership; quarantining is the conservative choice until evidence exists. Apply equivalent guarantees to Android JSON and iOS SwiftData.
2. **Legacy protocol (R02):** accept the actual v1 response with `firstAt`/`lastAt`; retain both instants, validate the entire response, and downgrade only for the specifically negotiated unavailable response. Never advance a v2 upload cursor from a v1 acknowledgement.
3. **Invalid dates (R03):** exclude invalid individual contributions before aggregation; do not delete or rewrite ambiguous records and do not lose valid contributions sharing an identity.
4. **Account adoption and bootstrap (R04, R07, R18):** activation and owner-scoped loading precede synchronization, fenced by the same identity/generation. A per-owner durable decision tracks eligibility and an in-progress bootstrap; actual user-generated sessions, expressions, exam attempts, lessons, marks and changed preferences count as data, default preference rows alone do not. In-progress eligible downloads resume after restart. Imports/reset and account changes invalidate stale work without silently authorizing a new download.
5. **Continuation (R05–R06):** compare cursor components in precisely the tuple ordering used to sort entries; parse existing delimiter cursors when valid, otherwise restart the pass and rely on idempotent replay. Persist each accepted download page and its cursor transactionally before the next request. Do not change the existing server identity order.
6. **Feedback (R08):** expose an observable owner-scoped state and retry path. Cancellation for an old owner must not become an error for the next owner. Never show or log tokens or full payloads.
7. **iOS compile/test fixes (R09–R10):** verify the suspected defects and correct source/test references and ordering fixtures. Lack of Swift/Xcode on Linux is an explicit verification gap, not an observed RED or GREEN.
8. **Manual voice (R11–R14):** silence waiting and active speech use distinct bounds. Preserve the beginning of speech and bounded memory. Do not submit a manual turn automatically at a cap: retain a bounded prefix and emit a recoverable, localized user notice instead of terminal `onFailure`. Synchronize initial greeting instruction, greeting completion and first turn without timing sleeps. Keep microphone mute actionable during unrelated pending work.
9. **iOS interaction, identity and audio (R15–R19):** preserve edits made after send and make any in-flight state visible; invalidate a rejected session in all consumers even when Keychain deletion fails, including restart handling without persisting new secrets. Capture and fence pronunciation owner and data generation. Serialize session adoption with bootstrap. Coordinate audio activation ownership rather than globally disabling audio another component owns. Where a reported interleaving is only suspected, first reproduce it or record the limitation.

## Verification

Follow test-first: observe the relevant failure before production edits when a deterministic runner exists; add public-flow regression tests for ownership, failure, retry, ordering and persistence, not only helpers. Use isolated test data and preserve existing files. Run Android focused tests then app and engine suites, lint and APK/UI-test assembly. Run `make check` and isolated `make test-api` when contracts/schema change. Run Swift Core, App/AppTests and physical Android/iOS audio/accessibility gates where available; keep all unavailable proof open and record exact commands/results. Review high-risk ownership, credential, persisted cursor and async changes independently before a work-unit commit. No source code or generated files may be changed merely to hide a failing test.
